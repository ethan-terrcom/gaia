# Gaia

A local-first control plane for a hierarchy of AI coding agents: a lead engineer agent
(Claude) that plans and reviews, junior agents (DeepSeek) that implement in isolated git
worktrees, and a human approval inbox for every irreversible step.

- What and why: [docs/PROJECT_BRIEF.md](docs/PROJECT_BRIEF.md)
- How: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
- Work packages: [docs/implementation/00-README.md](docs/implementation/00-README.md)
- Backend overview: [backend/README.md](backend/README.md), with detailed guides and Python
  explainers in [docs/backend/](docs/backend/README.md)

## Quickstart

```sh
make setup         # backend + frontend dependencies, and the pre-commit hooks
make migrate       # create or upgrade ~/.gaia/gaia.sqlite (Alembic)
make check         # lint, typecheck, test and secret scan (exactly what CI runs)
make dev-frontend  # UI on http://127.0.0.1:5173
make dev-backend   # API on http://127.0.0.1:8765, reloading on change
```

Run `make` with no arguments to list every target.

## The API

`make dev-backend` serves on `127.0.0.1:8765`; host and port come from `GAIA_HOST` and
`GAIA_PORT`, and `Settings` refuses anything but a loopback address unless
`GAIA_ALLOW_REMOTE=true` is set. `GET /api/health` answers without a token; every other route
needs `Authorization: Bearer <token>`.

That token is generated on the first start and kept in the Keychain, so the UI never asks for
it:

```sh
uv run --project backend gaia ui    # prints http://127.0.0.1:5173/#token=<token>
```

Open the printed URL: the token stays in the fragment (which a browser never sends to a
server), the UI moves it into `sessionStorage` and strips it from the address bar (doc 16).
`gaia secrets set GAIA_API_TOKEN` is refused on purpose - Gaia generates this one itself.
An error is always `{"error": {"code", "message", "request_id"}}`, and the same id is in the
`X-Request-ID` response header, so a report can be traced to a log line.

## Secrets

API keys live in the macOS Keychain. They never enter the repo, a `.env` file or your
shell profile, and the `gaia` CLI reads them from a prompt so they do not land in `argv`
or your shell history either. `gaia` is a console script of the **backend** project, so
either `cd backend` first or pass `--project backend` as below (from the repo root without
it, `uv` reports `Failed to spawn: gaia: No such file or directory`):

```sh
uv run --project backend gaia secrets set ANTHROPIC_API_KEY   # prompts, no echo
uv run --project backend gaia secrets set DEEPSEEK_API_KEY
uv run --project backend gaia secrets set GITHUB_TOKEN
uv run --project backend gaia secrets list                    # set / not set, never a value
uv run --project backend gaia secrets delete GITHUB_TOKEN
```

Set the ones you need: `ANTHROPIC_API_KEY` for the lead (planning and review, doc 07) and
`DEEPSEEK_API_KEY` for the junior subagents - they reach DeepSeek through the LLM gateway,
which reads the key from your Keychain, so it is stored with the same command (doc 07b).
`GITHUB_TOKEN` is for PRs and checks (doc 15). A missing key is only demanded when a feature
first uses it, so `secrets list` showing `not set` is not an error until then.

`GAIA_API_TOKEN` is generated by Gaia itself (doc 04), so `gaia secrets set` refuses it.

**Already have a key exported in `~/.zshrc`?** Store it with `gaia secrets set`, delete that
`export ...` line, open a new shell, then **rotate the key** in the provider's console: it has
been sitting in plaintext on disk, so any backup, dotfile sync or screen share has seen it.

Settings are read from `GAIA_*` environment variables (for example `GAIA_PORT`); a `.env` file
is never read.

## Repository layout

```
backend/    Python 3.12 package `gaia` (FastAPI, LangGraph), managed with uv
frontend/   Vite + React + TypeScript UI
docs/       brief, architecture, decisions and implementation work packages
```

The database is a single SQLite file at `~/.gaia/gaia.sqlite` (WAL mode), created and
upgraded by `make migrate` from the migrations in `backend/alembic/`. The path follows
`GAIA_DATA_DIR`, and LangGraph keeps its own checkpoints in a separate file next to it.
Tenant scoping goes through `gaia/db/repo.py`: no service queries a domain table directly.

## Conventions that tooling enforces

- **Secrets never touch the repo or env files.** API keys live in the macOS Keychain
  (doc 02). gitleaks runs in pre-commit and CI.
- **Only `gaia/services/proc.py` may spawn processes**, and never through a shell. Ruff
  rejects `subprocess`, `os.system` and similar imports everywhere else.
- **Strict typing.** mypy runs in strict mode on the backend. TypeScript runs in strict mode on the frontend.
- **Warnings are errors in tests**, so un-awaited coroutines fail the build.
- **Exact dependency versions.** `uv.lock` pins the backend, and `package.json` holds exact
  versions with no `^`. npm install scripts are disabled (`frontend/.npmrc`).
