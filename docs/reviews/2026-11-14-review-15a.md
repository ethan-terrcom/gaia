## Summary for the owner
Gaia can now push an agent's branch, open a draft PR and merge it after approval, without the
GitHub token ever touching argv, a URL, git config or a file. The junior's code was careful about
the token, and every token test passed.

Review found **two bugs that would have broken every merge** and one that hid merges after a
failure:
- G2: GitHub won't merge a draft, and Gaia opens drafts;
- G1: remote branch cleanup silently never happened;
- P2: a failed cleanup could roll back the record of a merge that GitHub had already done.

All three are fixed and tested. Two checks against real GitHub passed: a bad token is reported
cleanly, and a push authenticates through the helper without leaking. **I need a sandbox
repository and a fine-grained token from you** for the end-to-end test; see the open item.

## Findings
| # | Severity | Where | Finding | Resolution |
|---|---|---|---|---|
| G2 | **High** | `pull_requests.merge` | PRs are opened as drafts, and GitHub refuses to merge a draft (405 "still a draft"). Every merge would have failed with `MergeBlocked`. | **Fixed:** `GitHubClient.mark_ready_for_review` (GraphQL `markPullRequestReadyForReview` on `node_id`; REST cannot) runs before `merge_pr`. Tests cover the order, the variables, a non-draft skip, a missing `node_id`, and GraphQL and HTTP errors. |
| G1 | **High** | `github.delete_branch` | The branch was encoded with `quote(safe='')`, so `gaia/abc` became `gaia%2Fabc`. GitHub's refs endpoint would 404, which the method treats as "already gone". Branches were silently never deleted. The fake transport matched httpx's **decoded** path, so the tests could not see it. | **Fixed:** the slash stays literal, and `GitHubFake` matches the raw wire path. Test: `test_delete_branch_keeps_the_slash_literal_on_the_wire`. |
| P2 | **High** | `pull_requests.merge` | The merged state and the branch delete shared one transaction, so a failed delete rolled back the record of a real merge. The "already merged on GitHub" path returned early, so a resumed node never deleted the branch or published `pr.merged`. | **Fixed:** the merged state is committed first; the delete is best-effort and logged; a resumed pass finishes the job; a pass that finds the row merged makes no GitHub call. Two tests. |
| P4 | Medium | `GitService.push` | The repository's own `.git/config` is read during the push. `url.*.insteadOf` could reroute it, with the token, to another host or to SSH with the owner's keys. `http.sslVerify=false`, `http.proxy` or `http.extraHeader` could expose the token. The config is not agent-writable (srt denies `.git`), so this is defence in depth. | **Fixed:** those settings are pinned on the command line, and a URL rewrite refuses the push. Tests: the argv pins, and a planted `insteadOf` blocks the push. |
| P1 | Medium | `pull_requests` | `open_pr` and `merge` held a DB transaction across a push of up to 120 s plus several API calls. | **Fixed:** the methods are restructured as load → network → persist, with a shared `_load`. |
| P3 | Low | `pull_requests` | A failed token check was cached for the process, so fixing the token needed a restart. | **Fixed:** only a pass is cached. Test. |
| P5 | Low | `pull_requests.merge` | The squash commit title was `Merge PR #7`. | **Fixed:** it is now `[gaia] <ticket title> (#7)`. |

**Checked and fine:**
- the token is registered for redaction;
- error messages are redacted and capped;
- `validate_push_url`, and branch prefix enforcement on push and delete;
- the askpass script content and its 0700 mode;
- `credential.helper=` resets the helpers;
- `--no-verify` and a hooksPath of `/dev/null` (the pre-push hook test);
- rate-limit handling (`retry-after`, the reset clock, the max wait);
- GET-only 5xx retry;
- strict response parsing;
- `@`-mention neutralising in PR bodies;
- the argparse CLI never prints the token.

## Live verification (lead)
- `GitHubClient.get_repo` against `api.github.com` with an obviously fake token →
  `GitHubAuthError 401 "Bad credentials"`; the token is absent from the message.
- `GitService.push` of a real worktree branch to `https://github.com/octocat/Hello-World.git` with
  the fake token → GitHub answered `Invalid username or token`. The askpass helper supplied the
  credential, git did not prompt, it failed in about a second, and the token is absent from the
  `GitError`.

## Lessons for the skills
- **A fake that decodes hides encoding bugs.** Mock transports should match what goes on the wire
  (`url.raw_path`), not a parsed view of it. This goes into the review skill's
  "stubs hide wrong request shapes" row.
- **Know the platform's state machine.** "Open as draft" and "merge" were each correct on their
  own; together they could never work. A handoff that chooses a non-default state must say how
  the flow leaves it.
- **Commit the irreversible fact first.** When step N cannot be undone (a merge), record it before
  the cleanup steps that can fail.
