## Findings
| # | Severity | Where | Finding | Resolution |
|---|---|---|---|---|
| B1 | Low | `db/repo.py` `list_with_context` | Only the PR row was workspace-filtered; the joined run, ticket and repository were not. That is safe today (one workspace), but the FKs do not enforce a shared workspace (F5). | **Fixed:** every joined table is scoped. |
| B2 | Low | `services/pr_sync.py` | Being offline (`httpx.ConnectError`) fell into the generic handler, so a full traceback was logged every 60 s on a laptop without Wi-Fi. | **Fixed:** one `pr_sync.offline` warning per round. Test. |

**Checked and fine:**
- `ci_rollup` covers every row of the decision table, including GitHub's "pending with 0
  statuses", and treats `neutral` and `skipped` as passing;
- `review_rollup`: latest decisive review per user, with a dismissal clearing an approval;
- `watch_ci`:
  - it pins the worktree HEAD;
  - events go out on change only, and backoff resets on change;
  - no CI gets a grace period, then `unknown` and pass;
  - timeout → `failed`, recorded in the row too;
  - a rate limit sleeps; no transaction is held across the network;
- `PRSyncService`:
  - no token → silent;
  - one PR failing doesn't stop the round, and a rate limit ends it;
  - each update is its own transaction;
  - `CancelledError` propagates, so the lifespan stops it;
  - tests disable it in the shared settings;
- migration `0005` uses batch mode and has a downgrade;
- the PR list is one joined query, newest first, and needs the token.
