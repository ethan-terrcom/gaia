# Review: 12a — orchestrator skeleton on fakes

**Reviewer:** lead engineer (Claude), pair-reviewing as doc 12 requires · **Implemented by:** DeepSeek junior, in two sessions
**Date:** 2026-11-14 · **Branch:** `impl/12a-orchestrator-skeleton`

## Verdict
**Approve after lead fixes.** All the hard properties are proven by tests against a real
`AsyncSqliteSaver`:
- **crash recovery** with no duplicate rows;
- no duplicate approval on resume;
- a budget pause and resume;
- a revise loop into escalation;
- concurrency limiting;
- the full happy path to merge.

The node code is thin, and every gate upserts before it interrupts. The lead fixes concern
routing, budget semantics and `RunManager` robustness.

## How it was built
The first junior session hit the 240-turn cap with most of the work done: 8 of 8 graph tests
passing, coverage at 98%, and the diagram and docs missing. The lead measured what existed and
dispatched a **part 2** handoff listing the exact failing tests, missed lines and missing files.
Part 2 finished in **79 turns** without changing production behaviour, and refused to loosen
`RUN_TRANSITIONS` to make a test pass. This is now in the `write-junior-handoff` skill.

## Findings

| ID | Severity | Where | Finding | Status |
|---|---|---|---|---|
| R5 | **Medium** | `graph.py` | Conditional edges had **no path maps**. LangGraph silently drops a route to an unknown node, so a typo'd route name would quietly stop a run mid-workflow. The generated `docs/graph.md` showed **4** of 28 edges. (The "end" routes still ended, but only because of that silent drop.) | **Fixed:** an explicit path map on every conditional edge. Tests: the edge set is declared, and an unknown route **raises**. The diagram now shows all 28 edges. |
| G1 | Medium | `with_guard` budget gate | "Approve" without a `budget_usd` continued at the exhausted cap, so the gateway would 403 the next call and the run would fail. `budget_usd` was only checked to be > 0, not above what had been spent. | **Fixed:** approving without a number grants another `settings.run_budget_usd`, and a new cap must exceed what was spent. |
| R1 | Medium | `RunManager.resume` | It did not refuse a run whose task was still executing; two `ainvoke`s on one checkpoint thread would race. | **Fixed:** `RunBusy` (doc 14 → 409). |
| R2 | Medium | `RunManager._launch` | Graph errors other than `RunFailed` (a bad resume value, a checkpoint error) were stored in `_errors` and **never logged**. | **Fixed:** `orchestrator.run_errored` is logged with the error class. |
| R3 | Low | `RunManager.cancel` | It looked the run up without a workspace (F5 class). | **Fixed:** `cancel(run_id, workspace_id=…)`. |
| R4 | Low | `RunManager._tasks` | Finished tasks were never pruned. | **Fixed:** pruned on each launch. |
| A1 | Low | `apply_decision` | `approval.decided_by` was never set. | **Fixed:** `Decision.decided_by`, which the API fills (doc 14). |
| P1 | Info | `domain/plans.py` | Packages 12a and 11 both created it. 11's version is kept, plus 12a's empty-title check. 12a's "revise must carry feedback" validator was **not** adopted: it would turn a slightly imperfect model reply into a failed review, and the prompt already asks for actionable feedback. | Resolved at rebase. |

**F3 (from review 01-05)** is closed here: `PENDING → PAUSED_BUDGET` and `PLANNING → PAUSED_BUDGET`
are added because the guard checks the budget before every node, and `failed` stays terminal.
