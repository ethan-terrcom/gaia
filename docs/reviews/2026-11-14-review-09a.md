# Review: 09a — path guard, command policy, sandbox profile (D1)

**Reviewer:** lead engineer (Claude) · **Implemented by:** DeepSeek junior (`deepseek-v4-pro`, sandboxed harness)
**Date:** 2026-11-14 · **Branch:** `impl/09a-security-core` · **Architect review requested:** yes (security-critical)

## Verdict
**Approve after lead fixes.** The junior delivered careful, readable and well-tested code:
- 112 new tests;
- a complete rule table in the doc;
- every escape hatch pinned to `false`;
- `srt` located only at a pinned path.

The review found one confinement bypass and four policy gaps. All are fixed on the branch with
tests. The sandbox was then proved against the real `srt` 0.0.81, with a negative control. Nothing
is left open, but two decisions below are worth the architect's eye.

## Findings

| ID | Severity | Where | Finding | Status |
|---|---|---|---|---|
| S1 | **High** | `paths.confine` | The `.git` check looked only at the input string. A symlink inside the worktree (`alias -> .git`, created by any command the agent runs) resolves into `.git` while every component of the input looks harmless, so `write_file("alias/config")` would have reached the worktree's git metadata, the F1 attack surface. | **Fixed:** the resolved path is checked too. 4 tests. |
| S2 | Medium | `commands._extra_allow_decision` | The owner-registered test command could never take effect. It was checked *after* the package-manager and shell tripwires, so `npm test` always asked, and its entries were not unwrapped, so `["uv","run","pytest"]` never matched. | **Fixed:** checked after deny and slash rules, before the tripwires; entries are unwrapped like the command; a bare `bash`, `python` or `npm` entry is ignored. **See decision D-a.** |
| S3 | Medium | `command_policy.default.toml`, `_allow_decision` | `rg --pre <prog>` runs an arbitrary program per file, and `deny_flags` matched only exactly, so `--pre=sh` would slip past any future long-flag deny. `find` lacked `-okdir`, `-fprint*` and `-fls`. | **Fixed:** `rg` denies `--pre`; long flags also match `--flag=value`; `find` list extended. |
| S4 | Low | `_unwrap`, `_has_setuid_flag`, deny list | Unwrapping ran only once, so `uv run python -m pytest` asked. Numeric setuid modes (`chmod 4755`) were not denied. `sudoedit` and `pkexec` were missing. | **Fixed:** iterative unwrap up to depth 4, octal setuid regex, deny list extended. |
| S5 | Medium | `sandbox.build_srt_settings` | Gaia's data dir (database, checkpoints) was protected only because it defaults to `~/.gaia`. With `GAIA_DATA_DIR` elsewhere, a sandboxed command could read `gaia.db`. Confirmed live. | **Fixed:** `SandboxSpec.data_dir` is read-denied and validated (`data_dir/worktrees` itself refused). Live test added. |
| S6 | Low | `classify_write`, `denyWrite` | `.envrc` (direnv runs it on `cd`), `.pre-commit-config.yaml` and `.husky/` run code on the owner's machine but were plain writes. | **Fixed:** `ask` in `classify_write`; `.envrc` write-denied in the sandbox. |
| T1 | Low | `tests/test_sandbox_live.py` | The `srt_path` fixture re-read `GAIA_SRT_PATH` after the autouse fixture had scrubbed `GAIA_*`, so the live tests errored whenever they were enabled. | **Fixed.** |

## Decisions for the architect
- **D-a: `extra_allow` outranks the shell and package-manager tripwires (S2).** The registered test
  command comes from the owner (D3: never from the repo). `bash scripts/test.sh` adds no risk beyond
  `pytest` importing an agent-written `conftest.py`; containment is the sandbox in both cases.
  Recommendation: keep this. The alternative leaves `npm test` and most non-Python repos asking on
  every step.
- **D-b: `git` is denied in `run_command` entirely** (junior's tightening, kept). Agents use 09b's
  git tools, which go through `GitService`'s hardened environment and the 05b worktree pin.

## Live verification (lead)
I installed `@anthropic-ai/sandbox-runtime@0.0.81` with `npm install --ignore-scripts` into a scratch
prefix and ran `GAIA_SRT_PATH=… uv run pytest tests/test_sandbox_live.py`: **5 passed**. The
cases are:
- a `conftest.py` reading an SSH key and opening a socket under `python -m pytest`;
- a write outside the worktree;
- a write into `.git/` (directory form);
- a rewrite of a worktree's `.git` *file*, the real F1 attack;
- a read of `gaia.db` in a data dir outside home.

**Negative control.** The same probe script, run with and without `srt`, using settings built for
the real home:

| Probe | Without `srt` | With `srt` |
|---|---|---|
| read `~/.zshrc` | allowed | **denied** (EPERM) |
| TCP to `1.1.1.1:443` | allowed | **denied** |
| write outside the worktree | allowed | **denied** |
| write inside the worktree | allowed | allowed |
| read a data dir outside home (before S5) | allowed | allowed: the S5 gap, now fixed |

## For 09b and 10
- 09b's file tools must call `confine()` *and* open with `O_NOFOLLOW` (or re-check after open). The
  resolve-then-use window is inherent to a path API.
- Build every `SandboxSpec` with `data_dir=settings.data_dir` and
  `gateway="127.0.0.1:<port>"`.
- `srt` on macOS shell-quotes the argv into one string for `sandbox-exec` (`shell-quote`, in
  `dist/cli.js`). It is quoted correctly in 0.0.81. Re-check this on any version bump.
