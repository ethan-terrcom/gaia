## Findings

| ID | Severity | Where | Finding | Status |
|---|---|---|---|---|
| L1 | **Medium** | `AnthropicClient.parse` | It used the SDK's non-streaming `parse` helpers, refused `max_tokens > 16000`, and could not send `cache_control` on the non-fallback path. The doc 08 spike saw a long non-streamed Opus planning call die mid-flight (502 after 97 s through the gateway; not reproduced). anthropic 2.8.0's `messages.stream` and `beta.messages.stream` both accept `output_format`, and `get_final_message()` returns `parsed_output`. | **Fixed:** `parse` always streams, caches the system prompt on both paths, and has no 16K cap. Tests updated. |
| L2 | Medium | `LeadEngineer.plan_ticket` | The one allowed retry after a denied `test_command` sent the policy's objections **without the rejected plan**. The model was asked to "revise" something it couldn't see, and the request had two consecutive user turns. | **Fixed:** the rejected plan is replayed as the assistant turn. The test asserts `user, assistant, user`. |
| L3 | Low | `gaia dev plan` | Logs went to stdout before the JSON (it can't be piped to `jq`), and the cost line said "4 input tokens" for a 12,898-token prompt, because it ignored cache writes and reads. | **Fixed:** logs go to stderr through a lazily resolved stream (binding `sys.stderr` directly broke later tests under pytest's capture), and the line counts every prompt token. |
| L4 | Info | `review_step` | The approved plan is sent outside `wrap_untrusted`. It is lead-generated and human-approved, but it can quote ticket text. | Accepted. Revisit in 18d if plans become editable by non-owners. |

lead-only launcher that puts the Anthropic key in an in-memory `SecretStore`; your Keychain was not
touched.

  is recorded against the seeded `lead` agent, and the run is `cancelled` with `budget_usd=5`.

  change its output to `gaia <version>` instead of adding a duplicate, kept the exit code and the
  no-subcommand behaviour, used `["uv","run","pytest",…]` (the repo's registered test command), and
  listed risks.
