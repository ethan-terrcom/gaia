# Review: 17f — Worktrees & repositories view

- **Date:** 2026-11-14 · **Reviewer:** lead engineer (Claude) · **Implementer:** DeepSeek junior
- **Handoff:** [`handoffs/17f-worktrees-repos-view.md`](../implementation/handoffs/17f-worktrees-repos-view.md)
- **Verdict:** **merge, with one lead fix.**

## Summary for the owner
The Worktrees page lets you register a repository, set its test and setup commands, and see every
worktree Gaia created. Each worktree shows its dirty, orphan, missing and tampered flags, a copy
button and an "Open in VS Code" link. You can remove a worktree safely: a dirty one needs its
branch name typed before Gaia discards uncommitted work. The junior also spotted that a
`.gitignore` rule from the scaffolding hid this view's files from git; I fixed the rule.

## Findings
| # | Severity | Finding | Resolution |
|---|---|---|---|
| V1 | Medium | The root `.gitignore` rule `worktrees/` matched `frontend/src/views/worktrees/`, so the view's files would never have been committed. The junior raised it as an open question. | **Fixed:** `/worktrees/`. |
| V3 | Low | Because oxlint honours `.gitignore`, it had also silently skipped this view: once V1 was fixed, 2 warnings appeared (state set inside an effect; unstable effect deps). | **Fixed:** the repository filter's fallback to "All" is derived during render, so there is no effect. |
| V2 | Info | The worktree list endpoint requires `repo_id`, so "All" makes one request per repository. | **Accepted:** a server-side "all" would run the same per-repo git checks. Recorded in doc 17. |

**Checked:**
- the VS Code link URI-encodes each path segment;
- the clipboard is used only when available;
- branch names, paths and remote URLs are plain text;
- 409/422 messages from the API are shown inline, never as a crash;
- removal goes through `ConfirmDialog`, with typed confirmation and `force=true` only for dirty
  worktrees;
- the command inputs explain "no shell";
- every section has loading, error and empty states.

## Lesson
- **An ignore rule can hide code from every tool at once:** from git, from the linter and from
  review. When a junior's new files don't show in `git status`, check `git check-ignore -v <path>`
  before anything else.
