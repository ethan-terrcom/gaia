## Found in the logs and events

1. **No later sandbox can use the venv that setup builds (#64).** The owner's "new test" run on Gaia
   itself passed setup. Then every `make test`, from the agent and from the checks, failed with
   `failed to canonicalize path .venv/bin/python: Operation not permitted`, and the step
   escalated and retried.
   - Why: uv had installed Python under setup's own throwaway `HOME`
     (`runs/<run>/setup-tmp`), which no later sandbox may read.
   - This was reproduced and verified against the real `srt`.
2. **`run.started_at` and `run.finished_at` are never written (#65).** Every run had both null. Two
   effects:
   - the dashboard's start times were blank;
   - `gaia worktrees cleanup` (which skips a terminal run with no `finished_at`) could never
     reclaim a worktree.
3. **No secrets leaked.** Eight patterns were checked in `gaia.jsonl` and in every event payload:
   Anthropic and OpenAI key prefixes, `gaia_rt_`, `Bearer`, `ghp_`, `github_pat_`, `#token=` and
   `token=`. The result was 0 hits for each.
4. **Noise, not bugs:**
   - Every Ctrl-C with a UI tab open logs `Exception in ASGI application … CancelledError`
     followed by a `KeyboardInterrupt` traceback. There were 4 such pairs. This is uvicorn
     cancelling an open SSE stream at shutdown.
   - One `address already in use` came from starting a second server on 8765.
5. **The farewell run failed at `open_pr: this repository has no GitHub remote`.** That is the
   demo repository, and the case is still the open owner question (no-remote runs → `completed`
   or `failed`).

## Follow-ups (not fixed here)
- **A failed or cancelled run leaves its ticket `in_progress` and its worktree `in_use`.** This was
  seen live: all three tickets are `in_progress`. Re-runs work regardless (#63), but the Tickets
  and Worktrees views overstate what is active. Recommendation: on a terminal run, move the ticket
  back to `ready` (or `done` on completion) and the worktree to `ready`.
- **The run detail doesn't show why a run failed** without opening the Timeline. `RunSummary` and
  `RunRead` have no error field. Recommendation: add `error` (the `run.failed` message) to the run
  read model, and show it on the run page and as a tooltip in the Runs list.
- **Shutdown noise:** handle `CancelledError` in the SSE generator, so that Ctrl-C does not log an
  ASGI exception.
- **Housekeeping:** three `pytest` processes from a 2026-11-14 session (10a worktree) are still
  running. They are harmless, but they should be killed.
