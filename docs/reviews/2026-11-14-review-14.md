## Summary for the owner
Everything a run needs is now an HTTP call: start it, watch it, cancel it, read its diff, and
**decide its approvals**. A merge still needs you to type `merge <PR number>`; nothing else will
do. The junior did careful work: 255 turns, the largest package so far, at 100% coverage. I made
one small fix so the merge approval itself carries the PR number.

## Findings
| # | Severity | Finding | Resolution |

| M1 | Low | The `approve_merge` node's payload had no `pr_number`, so the confirmation phrase came from a DB fallback and the inbox could not show the PR. | **Fixed:** the node stores `pr_number`; the fallback stays as defence. Asserted in the graph happy-path test. |

**Checked and fine:**
- **Decide:**
  - a per-approval `asyncio.Lock`, held across read, validate and resume (a recorded deviation:
    SQLite has no `FOR UPDATE`);
  - command approvals go through the shared broker → 200, with `ApprovalNotPending` → 409 and
    `LookupError` → 404;
  - graph gates go through a validated `Decision` → `resume` → 202, with `RunBusy` → 409;
  - `edit` is only for a plan, and the edited plan is validated (→ 422);
  - a merge requires the exact `confirm`;
  - the audit row stores a hash of `edited_payload`, never its body.
- **Runs:**
  - start → 404 for an unknown ticket, 409 if it already has an active run, a custom budget is
    stored;
  - the list is one statement with correlated subqueries (the limit applies to runs);
  - detail and cancel (409 when terminal);
  - `/diff` uses `diff` + `diff_worktree` (never `diff_since`; a test asserts the index is
    unchanged), is capped, and runs git outside DB sessions;
  - 503 when the orchestrator is off.
- The e2e test drives a whole fake run through HTTP only.
