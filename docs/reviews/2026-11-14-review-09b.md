## Summary for the owner
Gaia now has the one tool layer every agent uses, whatever model drives it: file tools, search,
commands and git, each audited, each emitting live events, and with commands always run inside
the OS sandbox. This is what makes ADR-001's portability rule P3 real: the tools are Gaia's, not
the model vendor's.

The junior's work was solid and thorough. 1,248 tests passed and coverage was 100% on delivery.
I found and fixed one **sandbox weakness** (S1) and one **audit-loss bug** (R1) that would have
appeared only under the Claude runtime. Both were reproduced before being fixed. Everything was
then verified live against the real sandbox. Nothing needs a decision from you beyond the
standing architect review of the security packages.

## Findings
| # | Severity | Where | Finding | Resolution |
|---|---|---|---|---|
| S1 | **High** | `tools/shell.py` | `SrtCommandRunner` wrote the sandbox's settings file into the task dir, which the sandboxed command can write. A process left running by one command (a daemonised child escapes the process-group kill) could rewrite the **next** command's sandbox rules between Gaia writing them and srt reading them, for example adding network access. | **Fixed.** Settings go to a fresh 0700 directory under `{data_dir}/sandbox/`, which the sandbox read- and write-denies, and are deleted after each command. The test asserts the location and the cleanup. |
| R1 | **High** | `tools/registry.py` | The audit write and the `agent.tool_result` event in `call()`'s `finally` were not shielded. Under the Agent SDK (10c), tool handlers run inside an anyio task group whose cancellation is level-triggered, so a cancelled run would lose the audit row for the call that was in flight. This is the same bug class as 07b's metering. | **Fixed.** `anyio.CancelScope(shield=True)` plus `move_on_after(10)`. It was reproduced first by `test_audit_survives_a_level_triggered_cancel_scope` (failed, then passed). |
| R2 | Medium | `tools/registry.py` | `summarize_args` ran outside the `try` in `_write_audit`, so a non-object `arguments` (a model can send `[]`) raised out of `finally`. | **Fixed.** Non-mapping args are refused ("arguments must be a JSON object") and audited as `{}`. Reproduced first. |
| F1 | Medium | `tools/fs.py` | A `read_file` line range was applied to the first 200 KB only. The truncation note tells the model "use start_line/end_line", but lines past 200 KB were unreachable. | **Fixed.** A ranged read scans up to 20 MB, and the output stays capped at 200 KB. Test with a 20,000-line file. |
| F2 | Low | `tools/fs.py` | `edit_file` loaded files of any size into the server's memory. | **Fixed.** Edits and ranged reads refuse files over `MAX_SCAN_BYTES` (20 MB). |
| F3 | Low | `tools/fs.py` | Error messages showed the model absolute host paths (`/Users/…/.gaia/worktrees/…`). | **Fixed.** Errors are relative or pathless; the audit row keeps the target. |
| R4 | Low | `tools/git_tools.py` | `git_diff` called two private `GitService` methods, because the handoff fenced `git.py`. | **Fixed.** `GitService.diff_worktree(location, *, path, staged)` is now public. |

**Checked and fine:**
- every path goes through `confine`;
- writes go through `classify_write`, with in-turn approval, and `O_NOFOLLOW` after confinement;
- `extra="forbid"` on all inputs;
- no `re` on model patterns;
- the rg argv is fixed, with `--no-config` and `RIPGREP_CONFIG_PATH` dropped;
- `command_env` never reads `os.environ`;
- `GitAuthor` validation;
- `wrap_argv`'s `env -u NO_PROXY`;
- `agent_path` validation;
- the DB audit sink runs in its own transaction and swallows failures;
- `summarize_args` hashes long content;
- no vendor imports.

## Deviations accepted
These are recorded in doc 09:
- `approve(..., tool=)` takes the tool name as a keyword;
- there is no `NeedsApproval` result: approvals stay in the turn (doc 10, requirement 8);
- `/opt/homebrew` is not added to the toolchain read list, because it is already readable
  outside `home`;
- search has two modes, as the handoff specified.

## Lessons for the skills
- **A sandbox's own config must live outside the sandbox.** Juniors put a helper file next to
  the task, because that is where the task's files are. Add it to the handoff skill's lead
  notes: "files that configure a boundary are written where the bounded process cannot write".
- **Shield `finally` in anything a harness may call from anyio.** This is the second time (07b,
  09b). It is already in the review skill's bug table; this case adds "the caller's task group,
  not your own code, decides the cancellation semantics".
- A package with this much surface (10 tools, 4 cross-module edits) used 209 turns. It finished,
  but at the edge: future packages this size should be split or given 260 turns.
