# Review: 18a — Daily-cap pause, new-run block, and the kill switch

- **Date:** 2026-11-15 · **Reviewer:** lead engineer (Claude) · **Implementer:** DeepSeek junior
- **Handoff:** [`handoffs/18a-budgets-kill-switch.md`](../implementation/handoffs/18a-budgets-kill-switch.md)
- **Verdict:** **merge, with one lead fix (B1).**

## Summary for the owner
Gaia can now be left running without surprises on the bill:
- **The daily cap pauses runs**, not only blocks provider calls. A run that hits the workspace's
  daily cap pauses and asks you, just as a run over its own budget does. Approving does not lift
  the daily cap: it means "I raised it, or it's a new day; try again".
- **New runs are refused** while today's spend is at the cap (409 `daily_budget_exhausted`).
- **The kill switch:** `POST /api/v1/admin/pause-all` stops every running agent at once and holds
  every run in a new `paused` state, until `resume-all`. A restart never resumes a paused run on
  its own. The UI button is the next package (18a-2).

## Findings
| # | Severity | Finding | Resolution |
|---|---|---|---|
| B1 | **High** | On resume, the guard recomputed the budget scope instead of answering its pending approval. The normal way out of a daily pause is to raise the cap or wait for the next UTC day, then approve. In both cases the re-run found the cap no longer applied, skipped the interrupt, and **never applied the decision**: the approval stayed pending forever while the run went on. | **Fixed:** the guard answers the node's pending budget approval first. A regression test pauses, raises the cap, approves, and asserts the row is `approved` and the node ran. |
| B2 | Low | The junior's sandbox had no OpenAPI type generator, so `schema.d.ts` wasn't regenerated. | **Fixed by the lead.** The worktree setup step in the ops guide now installs `frontend/tools/openapi` too. |

**Checked:**
- the flag is set **before** tasks are cancelled, so nothing starts in between;
- runs queued on the semaphore count as live and are paused;
- a cancelled node does not mark its run failed (`CancelledError` is not an `Exception`);
- the flag file is 0600, written atomically and fsynced;
- startup `recover()` ignores `paused` runs and does nothing while the flag exists;
- gate approvals survive a pause, while in-turn command approvals expire with their agent;
- every admin mutation writes an audit row;
- `EventType` is unchanged, so the frontend's pinned list still matches.
