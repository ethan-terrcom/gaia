## Findings
| # | Severity | Where | Finding | Resolution |
|---|---|---|---|---|
| C1 | **High** | `runtimes/claude_agent_sdk.py` | `run_task` registered `asyncio.current_task()`, the caller's task, and `cancel()` cancelled it. The `CancelledError` was then caught and turned into a result without `uncancel()`, leaving the caller's task permanently "cancelling". The same root cause as 10b's N1. | **Fixed:** the session runs in a child task; `cancel()` interrupts the client, then cancels the child; a cancelled caller still propagates. |
| C2 | **High** | same | The wrapper (which builds the CLI's environment), the srt settings and the pid file were written into `task_dir`, the sandboxed CLI's writable `HOME`/`TMPDIR`. | **Fixed:** a 0700 control dir under `{data_dir}/sandbox/` (09b's rule), removed after. |
| C3 | Medium | same | `MCP_TOOL_TIMEOUT` = approval + 120 s = 720 s, but `run_command` allows 1,800 s, so the CLI would abandon a long test run that Gaia was still executing. | **Fixed:** approval + 1,800 + 120 s. The CLI honouring the variable was verified live first (below). |
| C4 | Low | `cli.py` | The dev run had `budget_usd = 0`, so the gateway refused the first call. Found live. | **Fixed:** `settings.run_budget_usd`. |
| C5 | Low | same | The runtime was named `claude_sdk`, but registries key runtimes by `RuntimeKind` (`claude_agent_sdk`). | **Fixed:** a `name` keyword, defaulting to the enum value. |

**Checked and fine:**
- `tools=[]` plus `disallowed_tools`, `strict_mcp_config`, `dontAsk`, exact `allowed_tools`, and
  the `PreToolUse` deny hook (P3);
- `setting_sources=[]`; Gaia's own prompts, never the preset;
- no `resume`, `continue_conversation`, `fork_session`, checkpointing or `total_cost_usd`,
  enforced by a source grep test (P4);
- `env -i` in the wrapper, with the token renamed from `GAIA_RUN_TOKEN` and never written to the
  script;
- `shlex.quote` on every interpolated path, and newline/NUL refused;
- the token minted per task and revoked in `finally`; usage priced by Gaia's `PriceTable`;
- the vendor-boundary test (10b) passes with this module.

## Live verification (lead)
A gateway server held both keys in memory, on scratch data and port 8799. The CLI process ran
under `env -i` with no keys; srt was the pinned 0.0.81; the model was Claude Opus 5.5.
1. **End to end:** `gaia dev run-task --runtime claude_sdk --worktree <toy uv project> "Add
   farewell(name)…"` → `completed`.
   - `files_changed` = `src/greet.py` and `tests/test_greet.py`; the tests pass in the worktree.
   - **$0.042**, whether priced by the runtime or by the gateway.
2. **Gaia's tools only:** the audit log shows exactly `read_file` ×2, `edit_file`, `write_file`
   and `run_command uv run --offline pytest -q`, all `allow`. No built-in tool can exist in this
   configuration.
3. **The gateway saw only `v1/messages`** (5 requests: 4 metered, plus 1 budget refusal from the
   C4 attempt). The run token was revoked, and `{data_dir}/sandbox/` was empty afterwards.
4. **Keys:** `grep -c` for both provider keys in the server log and the CLI output → **0**.
5. **`MCP_TOOL_TIMEOUT`:** with the value squeezed to 10 s and a 30 s test, the model reported
   the tool returned "MCP server "gaia" tool "run_command" timed out after 10s". So the bundled
   CLI honours it, which justified C3.

## Lessons for the skills
- **The same bug twice in one batch (N1/C1) means it belongs in the handoff template.** Any
  runtime handoff now says: "run the work in a child task; never register `current_task()`".
- **Test a harness's own limits live.** The SDK's tool timeout was undocumented in the
  junior's offline world. Five minutes of live probing turned a guess into a fix.
- **Part 2 for coverage is cheap.** 74 turns ($0.30–0.60) closed 58 lines once the design was
  settled. Don't let the lead write routine tests.
