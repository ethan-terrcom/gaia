## Verdict

Approved after two lead fixes and four extra tests. The F1 design is implemented faithfully:
- `WorktreeLocation` carries a pinned `GIT_DIR` and `GIT_WORK_TREE`, resolved only from the trusted
  repository's `.git/worktrees/*/gitdir` entries.
- Every in-worktree `GitService` verb requires that pin, and a bare path inside `worktrees_root` is
  refused.
- A changed `.git` file raises `WorktreeTampered` before git runs.

Migration `0002` backfills before tightening, and its upgrade, downgrade and drift checks are all
exercised. F6 uses FastAPI's `scope="function"` and is proven by a test that fails at commit time.
Final state: 362 tests, 100% coverage. Run cost: 17.5M prompt tokens (99% cache hits) and 80K output
tokens.

## Fixed by the lead

| # | Problem | Fix |
|---|---|---|
| L1 | **F2 was only half closed.** The timeout path was bounded, but the cancellation path still did an unbounded `await process.wait()`. A `setsid()` grandchild could therefore still hang a cancelled run, and doc 14 cancels runs. | Both paths use `_reap_after_kill`. New test: `test_cancelling_with_an_escaped_grandchild_is_bounded`. |
| L2 | `remove(force=True)` skipped the only `.git` check before `git worktree remove`, a verb that inspects the tree through the worktree's own `.git` file. | `GitService.verify_location()` runs before removal on every path. New test: `test_remove_with_force_refuses_a_tampered_worktree`. |
| L3 | The F1 tests proved only that the *tamper check* fires, not that the *pin* stops the attack (the real defence). | `test_the_pin_alone_stops_planted_config` disables the check and asserts nothing runs. |
| L4 | The integrity-error handler had a no-op `cast(...)` statement and never logged anything. The escape test leaked a 30 s sleeper whenever an assert failed. | Logs `api.integrity_error` (path only); cleanup moved into `finally`. |

## Accepted as built

- `_close_stream_reader` uses the private `StreamReader._transport`. asyncio offers no public way to
  close a pipe that an escaped grandchild holds open, the use is narrow and commented, and the tests
  run with warnings as errors.
- `_read_capped` swallows `CancelledError`. This is acceptable because only `run_proc` ever cancels
  those internal tasks, and it wants the partial output.
