# Review: 13 — Event bus & SSE

**Reviewer:** lead engineer (Claude) · **Implemented by:** DeepSeek junior (`deepseek-v4-pro`, sandboxed harness)
**Date:** 2026-11-14 · **Branch:** `impl/13-events-sse`

## Verdict
**Approve after lead fixes.** The bus, tickets and routes are clean, documented and well scoped:
- subscribe-before-replay ordering;
- redaction before persistence;
- the stream mounted outside bearer auth, with the ticket as its only credential;
- dev routes off by default;
- background tasks cancelled on shutdown.

The review found two behavioural bugs in the SSE generator and one resource leak. All three are
fixed, with tests. The acceptance criterion was then verified live with `curl -N`.

## Findings

| ID | Severity | Where | Finding | Status |
|---|---|---|---|---|
| E1 | **Medium** | `stream_events` / `sse_frames` | With no `Last-Event-ID`, the resume point defaulted to `0`, so **every new connection replayed the workspace's entire event history**, unbounded, as a single `replay(limit=None)` list held in memory. | **Fixed:** no resume point means live from now. Replays are paged (`REPLAY_PAGE_SIZE = 500`). `last_event_id` must be ≥ 0. |
| E2 | Medium | `sse_frames` | On a slow-consumer overflow, the client received a `stream.gap` frame and had to notice it, fetch a new ticket and reconnect. Nothing in the client contract (doc 17) said so. | **Fixed:** the generator heals the gap by replaying the missed range from the DB, so every event arrives once, in order. `stream.gap` stays an internal bus signal. |
| E3 | Medium | `StreamTickets.issue` | Every ticket's plaintext went into the redaction registry. That set is **never pruned** and `redact()` scans it on **every log line**, so a UI reconnecting about once a minute grows memory and per-log-line cost without bound. Gaia never logs the ticket, so registering it bought nothing. | **Fixed:** tickets are not registered; the reason is in the docstring. **07b's run tokens have the same shape; see that review.** |
| E4 | Low | uvicorn access log | `?ticket=…` appears in uvicorn's access log (stdlib, not redacted). It is harmless, because the ticket is single use and already redeemed by the time the line is written. Still, it is the F8 class. | Open → doc 18b (route stdlib/uvicorn logs through redaction, or drop query strings from access logs). |
| T1 | Low | `tests/test_sse_frames.py` | The gap test's mocked `replay` published new events on every call. That was valid for the old behaviour but loops forever once gaps are healed. | Replaced with a realistic overflow test (publish 5 into a queue of 2; receive seq 1–5 exactly once), plus tests for live-only and paged replay. |

## Live verification (lead)
Setup: a temporary `GAIA_DATA_DIR`, `alembic upgrade head`, then
`GAIA_PORT=8799 GAIA_DEV_ROUTES=true gaia serve`. Results:
- `POST /api/v1/stream/ticket` with the bearer token, then `curl -N "…/api/v1/stream?ticket=…"`,
  then `gaia dev fake-run --events 3 --interval 0.3`: the stream printed **7 frames live**, `id: 1`
  to `id: 7` (`run.status_changed`, 3 × `agent.message`, `agent.tool_call`, `agent.tool_result`,
  `step.finished`).
- Reusing the same ticket returned **401**.
- `grep -c <api token> server.log` returned **0**. The ticket appears twice, in uvicorn's access
  log (E4).

## Notes for later packages
- **10/12:** depend on `EventSink` only (`from gaia.services.events import EventSink`). Build a
  `BusEventSink(bus, workspace_id=…, run_id=…, agent_id=…)` per task.
- **07b:** its budget-exceeded event row should be published through the bus once both packages
  are on main. That wiring is done at the 07b merge.
- **17:** on stream error, fetch a new ticket and reconnect with `?last_event_id=<last id seen>`.
  Gaps never need handling client-side.
- **F9:** `seq` order equals delivery order only with one process and SQLite's single writer.
