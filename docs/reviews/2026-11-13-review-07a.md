# Code review: 07a — LLM clients & cost accounting

**Reviewer:** lead engineer · **Date:** 2026-11-13 · **Implementer:** DeepSeek junior (`deepseek-v4-pro`,
lead's sandboxed harness; handoff in `docs/implementation/handoffs/07a-llm-clients.md`) ·
**Branch:** `impl/07a-llm-clients`

## Verdict

Approved after four lead fixes. The structure is right:
- SDK types stay out of the rest of Gaia (neutral `LLMMessage`/`LLMResponse`/`LLMUsage`).
- Usage is recorded **before** an `LLMStop` is raised, so refused and truncated calls are still
  costed.
- Keys arrive only as `SecretStr` constructor arguments.
- Logs carry metadata only.
- Prices are editable TOML, and the tests never read the shipped file.

Every SDK call matches anthropic 2.8.0 and openai 3.51.0, which I spot-checked against the installed
sources. The junior's own checks were green (398 tests, 100% coverage). Run cost: 122 turns, 16.1M
prompt tokens (99% DeepSeek cache hits) and 74K output tokens.

## Fixed by the lead

| # | Problem | Fix |
|---|---|---|
| L1 | `tool_choice` was sent on every Anthropic request. The API rejects `tool_choice` without `tools` (400), so every tool-less call, planning included, would have failed. The stub-based tests could not see it. | Sent only with tools; a test pins both cases. |
| L2 | With refusal fallback, `message.model` is the model that served the request. If `prices.toml` doesn't list it, `PriceTable.quote` raised `KeyError` **after** the call was billed, and the usage row was lost. Both clients had the same issue. | `PriceTable.quote_or_price_as()` prices an unknown serving model at the requested model's rates and records `price_tier="priced-as-requested"`. Clients also call `PriceTable.require(model)` at construction, so a misconfigured model fails before any spend. |
| L3 | DeepSeek's `reasoning_content` was not returned in `LLMResponse`, so a thinking-mode tool loop couldn't send it back as the doc requires. | `LLMResponse.reasoning_content`, read from the attribute or `model_extra`; three tests. |
| L4 | `make smoke-llm` used `max_tokens=64`. Opus 5.5 always thinks, and thinking counts against `max_tokens`, so the smoke call would end in `LLMStop("max_tokens")`. `_secret()` was typed `object` (hidden because `scripts/` is outside mypy). | `SMOKE_MAX_TOKENS = 2048`; `SecretStore` type. |

## Open items for the owner

- **DeepSeek prices are placeholders** (`# VERIFY:` in `gaia/llm/prices.toml`), and off-peak pricing is
  disabled until you confirm the real rates and window.
- **`make smoke-llm` is yours to run.** It reads `ANTHROPIC_API_KEY` and `DEEPSEEK_API_KEY` from the
  keychain (`gaia secrets set …`). Both are currently unset there; your keys are exported from
  `~/.zshrc`.

## Notes for later packages (no action now)

- Malformed tool-call JSON from DeepSeek becomes `{}` silently. Doc 10's runtime should treat an empty
  `arguments` for a tool with required fields as an error result, not as a call.
- The Anthropic client converts text-only messages; tool loops (`tool_use`/`tool_result` blocks) arrive
  with doc 10 or 11.
- Refusal-fallback billing is approximated by the final `message.model`. Per-iteration usage
  (`usage.iterations`) can refine it in 07b's gateway.
