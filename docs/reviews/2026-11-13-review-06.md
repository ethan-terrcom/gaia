# Code review: 06 — Repositories & tickets API

**Reviewer:** lead engineer · **Date:** 2026-11-13 · **Implementer:** DeepSeek junior (`deepseek-v4-pro`,
lead's sandboxed harness; handoff in `docs/implementation/handoffs/06-repos-tickets-api.md`) ·
**Branch:** `impl/06-repos-tickets-api`

## Verdict

Approved after four lead fixes. The API follows every convention from docs 04 and 05b:
- Routes are authenticated through the router and workspace-scoped through `Scoped`.
- Parents are loaded in the caller's workspace before a child is written (review F5).
- Status moves go through `transition()`.
- Worktree dirtiness uses the pinned `WorktreeLocation`.
- Every mutating route writes an audit row.
- Error handlers return fixed sentences, never exception text.

Ticket search escapes `LIKE` wildcards and binds the pattern as a parameter. Final state: 495 tests,
100% coverage. Run cost: 18.8M prompt tokens (99% cache hits) and 96K output tokens.

**Acceptance criterion verified live by the lead.** With `gaia serve` on a temporary data directory
and port, `curl` registered a repository, created a ticket, received 409 for `backlog → done`, listed
worktrees and the two seeded agents, received 409 for unregistering a repository that has tickets, and
received 401 without a token. The bearer token appeared zero times in the server log.

## Fixed by the lead

| # | Problem | Fix |
|---|---|---|
| L1 | **`DELETE /repositories/{id}` erased history.** The foreign keys from `repository` cascade (tickets → runs → approvals, usage, events), so "unregister" silently deleted every ticket and run of that repository. | Refused with 409 while the repository has tickets or non-removed worktrees. A repository that was registered and never used can still be unregistered. |
| L2 | **Remote URLs kept embedded credentials.** `https://user:token@host/…` was stored, returned by the API and logged. The junior also had to call the private `GitService._invoke` (git.py was off-limits to it). | New public `GitService.remote_url()`, which strips userinfo (`strip_url_credentials`) for every caller. scp-style `git@host:…` is unchanged. |
| L3 | **Orphan worktrees were reported as tampered** (a missing `.git` file fails the check), or could fail the whole list for a pre-0002 row. | The dirty and tamper check runs only for worktrees that exist and that git knows. Orphans report `dirty: null, tampered: false`. |
| L4 | The generated `frontend/src/api/openapi.json` would fail CI's `prettier --check`. | Listed in `frontend/.prettierignore`, since it is a generated file. |

## Accepted as built

- `tests/test_route_functions_direct.py` calls route functions directly. Coverage doesn't trace lines
  that run under SQLAlchemy's greenlet bridge during an ASGI request (the same limitation doc 03 hit),
  so these calls keep the 100% bar honest. The HTTP tests remain the contract.
- Migration `0003` (command columns `Text` → `JSON` argv lists) is hand-written and verified by
  `test_migrations.py` (upgrade, drift, downgrade). Old text values become one-item lists; no rows
  existed before this API.
- Duplicate `local_path` is checked in the route, not by a database constraint. That's adequate for a
  single local user.

## For the owner

- **Unregistering a used repository** is now refused rather than destructive. If you want to retire a
  repository that has history, the natural next step is an `archived` flag (hidden from lists, kept for
  history) rather than a delete. Tell me if you want that added to a later package.
