## Summary for the owner
The dashboard at `/` shows, at a glance:
- the active runs, with their step and cost against budget;
- how many approvals need you, and the oldest of them;
- open PRs with CI status;
- today's spend by provider;
- the last 14 days (success rate, average cost per run, cost per day).

Each card loads and fails on its own, so one broken endpoint never blanks the page.

## Findings
| # | Severity | Finding | Resolution |
|---|---|---|---|
| A1 | Info | Active runs come from `GET /runs?limit=100`, filtered client-side to non-terminal statuses. An active run older than the 100 newest would be missed. | **Accepted** at this scale. A server-side `active=true` filter is a follow-up if needed. |
| A2 | Info | The current step shows as "Step n: title"; the list endpoint has no step total, and fetching each run's detail would make one failing request blank the card. | **Accepted** (recorded by the junior as a deviation). |

**Checked:**
- agent and repo text renders as plain text;
- external links only to `https://github.com/`, with `noopener`;
- loading, error-with-retry and empty states;
- API errors (409/422/503) shown inline;
- query keys match the event stream's invalidation prefixes, so the view is live;
- the current global `fetch` is passed per request, as in 17e/17f.

## Live browser check

- the **production build** with the CSP meta tag, behind `vite preview` on `127.0.0.1:5173`;
- the real API on `:8765`, run from current main;
- the database from live E2E run 1, which holds two real runs (one failed at `open_pr`, one

  a pending approval of each remaining kind, and an open PR row.

**Every check passed**, with no console errors, page errors or unexpected HTTP errors. The checks
covered each view's data, navigation, hotkeys and decisions. The only console output was a known
warning: `frame-ancestors` is ignored in a `<meta>` CSP. It belongs in the HTTP header; see the
follow-ups.
