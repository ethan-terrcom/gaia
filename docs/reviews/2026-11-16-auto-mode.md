# Auto mode for agent commands (2026-11-16)

**Asked for by the owner:** "allow the agents to run in auto mode, in the same way that I can
allow Claude to run in auto mode … both for Claude and DeepSeek, but let the user pick
individually." Built by the lead directly (no junior package), like the 2026-11-15 live-use fixes.

## What was built
- `gaia/orchestrator/auto_mode.py`: `AutoModeSwitch`, a 0600 JSON file
  (`<data_dir>/auto-mode.json`) with one boolean per `ModelFamily` (`claude`, `deepseek`). It
  is written atomically, like the pause flag. A missing, unreadable or malformed file, or any value
  other than JSON `true`, means **off**.
- `ToolContext.auto_approve`: a callable bound by `wiring.py` to the runtime's family (native →
  DeepSeek, Claude Agent SDK → Claude). `approve()` consults it only when the caller passes
  `auto_mode_applies=True`, and only `run_command` does. It answers
  `ApprovalDecision(approved=True, auto=True)` without writing an approval row; the tool result
  and the audit row carry the new decision `auto_approved`.
- `GET`/`PATCH /api/v1/admin/auto-mode`, token-protected, audited as `admin.auto_mode` with the
  before and after state, 503 without the orchestrator (like pause).
- Settings page: one switch per family, with what it does and does not cover. The run timeline
  shows "ok (auto-approved)".

## Decisions (lead's, open to the owner)
| # | Decision | Why |
|---|---|---|
| AM1 | Auto mode covers **command** asks only. Protected-file writes (CI workflows, `.pre-commit-config.yaml`, `.husky/`, `.envrc`, agent config, lockfiles) still ask. | Those files run code **outside** the sandbox, on the owner's machine, the next time a hook, CI or direnv fires. They are rare in practice: all 15 approvals the owner had answered were commands (14 of them `npm`). |
| AM2 | Plan, escalation, budget, PR and merge gates are unchanged. | The request was about commands. A PR or merge is the irreversible step. |
| AM3 | Per **model family**, not per model id or per role. | The owner asked "Claude and DeepSeek". In demo mode both roles run on the native (DeepSeek-family) runtime, so the DeepSeek switch governs both there. A third runtime (Cline) would need its own family. |
| AM4 | State is a file in the data dir, not a DB row. | Same reasoning as the pause flag (18a): single-user, survives restarts, no migration. The sandbox denies the data dir, so an agent cannot switch it on. |
| AM5 | Read on every ask; a command already waiting is not auto-approved when the switch flips. | Immediate effect without a restart, and no approval is answered retroactively without the owner seeing it. |

## Verification
- `make check`: ruff, mypy, pytest 1946 passed at 100% coverage, 131 frontend tests, gitleaks.
- Unit and API tests: switch fail-closed cases, atomic write, family routing in the real wiring,
  `auto_approved` on an ask command, deny still denies, protected write still asks, PATCH partial
  update plus audit rows, 401 without a token, 422 for an unknown family.
- **Live, real `srt` sandbox and real wiring, fake LLM, scratch data dir on port 8799:** the
  native runtime ran a task whose command (`uname -s`) the policy asks about.

  | Switches | Approval row | `run_command` decision |
  |---|---|---|
  | both off | `command`, expired after 30 s | `ask_rejected`, not run |
  | Claude only | `command`, expired | `ask_rejected`, not run |
  | DeepSeek on | none | `auto_approved`, exit 0 in the sandbox |

## Follow-ups
- Commands in auto mode still run with **no network**: `npm install` of a new package will fail
  inside an agent turn whatever the approval. Only setup has the registry allowlist (A2).
- A visible "Auto mode" indicator in the top bar, like the demo badge, if the owner wants one.
