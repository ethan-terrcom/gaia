## What it's for

This part answers three questions for the rest of the backend: **how is Gaia configured** (typed
settings from `GAIA_*` environment variables), **where do credentials live** (the OS keychain,
behind an interface), and **how do secrets stay out of logs** (a redaction layer that every log
line passes through).

## How it works

### Settings

`Settings` is a pydantic-settings model. Every field can be set with an environment variable named
`GAIA_<FIELD>`:

| Field | Default | Notes |
|---|---|---|
| `data_dir` | `~/.gaia` | Forced to mode `0700` by `ensure_data_dir()` |
| `db_url` | `sqlite+aiosqlite:///<data_dir>/gaia.sqlite` | Derived from `data_dir` unless set |
| `checkpoint_path`, `worktrees_root` | under `data_dir` | Derived the same way |
| `host`, `port` | `127.0.0.1`, `8765` | Any non-loopback host is rejected unless `allow_remote=True` |
| `lead_model`, `junior_model`, `junior_base_url` | `claude-opus-5-5`, `deepseek-v4-pro`, DeepSeek's API | |
| `run_budget_usd`, `daily_budget_usd` | `5.0`, `20.0` | Must be > 0 |

The derived fields use a `default_factory` that receives the already-validated `data_dir`
(pydantic ≥ 2.10). That is why `data_dir` must stay the **first** field: a factory only sees fields
declared above it.

`get_settings()` builds the object once per process. Code that needs settings takes a `Settings`
argument, so tests can pass their own; only entry points (`cli.py`, `create_app()`) call
`get_settings()`.

### Secrets

```
gaia secrets set DEEPSEEK_API_KEY ──getpass──▶ KeyringSecretStore.set ──▶ macOS Keychain (service "gaia")
                                                       │
                                                       └─▶ register_secret(value)   (mask it from now on)
```

- `SecretName` is a closed list. Anything else can't be stored, and the CLI rejects unknown names.
- `get()` returns a `SecretStr` or `None`. `require()` raises `MissingSecretError`, whose message is the
  command that fixes it.
- Every value a store hands out is registered for redaction automatically, so a key that later shows
  up in a log line or an error message is masked even if the caller never thought of it as a secret.
- `GAIA_API_TOKEN` is generated by Gaia (`ensure_api_token()`, 32 random bytes) and can't be set by
  hand.

### Redaction

`redact(text)` replaces, in order:
1. every registered secret value (longest first);
2. known token shapes: `sk-ant-…`, `sk-…` (20+ characters), `ghp_…`, `github_pat_…`, and the
   credential after `Bearer`.

`redaction_processor` applies `redact` to every string inside a log event, recursively through dicts
and lists. `configure_logging()` puts it after exception formatting (so tracebacks are masked) and
just before the renderer (so nothing prints an unmasked event). The API error envelope and
`GitError` messages call `redact()` directly.

## Why it's built this way

- **No `.env` support, on purpose.** A plaintext key file next to a repo is exactly what Gaia
  removes. A test fails if `Settings` ever gains an `env_file`, or a field whose name looks like a
  credential.
- **`localhost` is rejected as a bind address.** It's a name, which `/etc/hosts` can point anywhere;
  only loopback IP literals pass. (The `Host` *header* check in the API still accepts `localhost`:
  that's a different thing, explained in doc 02's hand-off note.)
- **Deleting a secret doesn't un-register it from redaction.** A traceback captured earlier may not
  have been printed yet, and masking a retired value costs nothing.
- **Values shorter than 8 characters aren't registered.** Masking every `"main"` or `"true"` would
  destroy the logs.

## Changing it safely

- **Adding a setting:** add the field with a safe default, and document `GAIA_<NAME>` in the field's
  docstring. If it's derived from `data_dir`, declare it after `data_dir`. Never add anything secret;
  it belongs in `SecretName`.
- **Adding a secret:** add it to `SecretName`. The CLI picks it up automatically. If Gaia generates
  it, refuse it in `_secrets_set` like `GAIA_API_TOKEN`.
- **Adding a token shape to redact:** add the pattern to `_PATTERNS`, more specific patterns first,
  with a test in `tests/test_redaction.py`.
- **Tests:** `tests/conftest.py` gives every test an in-memory keyring, an empty redaction registry
  and no inherited `GAIA_*` variables. The one real-keychain test is `@pytest.mark.live`.
